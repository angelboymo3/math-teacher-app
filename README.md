# 풀이과정 · 수학 수업 노트

고등학교 수학 교사의 한 학기 수업 운영을 한곳에 모으는 웹앱입니다. 대학 수업 기말 과제이자 실제 수업을 위한 도구로 발전시킵니다.

## 첫 버전

평가 계획 / 수행평가 / 수업자료 / 정기고사 / 세특 기록의 5개 탭과 빈 화면을 제공합니다. 탭을 클릭하거나 키보드 방향키, Home, End로 이동할 수 있습니다. 주소 끝에 선택한 탭이 남아 새로고침·뒤로 가기에도 사용할 수 있습니다.

현재는 **① 저장·백업 기초**까지 제공합니다. 빈 보관함을 브라우저에 저장하고 JSON 파일로 내보내거나 가져올 수 있습니다. 학기·과목 관리, 평가 계획 작성, 자료 관리, 학생 기록은 아직 제공하지 않습니다. 5개 탭은 기존 빈 화면을 유지합니다.

## 열어 보기

- 공개 주소: https://angelboymo3.github.io/math-teacher-app/
- 내 컴퓨터: 내려받은 폴더의 `index.html`을 브라우저로 엽니다.

- JavaScript가 꺼져 있으면 평가 계획의 안내 화면만 표시됩니다.

## 개인정보와 백업

이 저장소와 배포 사이트는 공개용입니다. 실제 학생 이름, 성적, 세특, 비밀 키를 코드·문서·캡처·Git 기록에 넣지 않습니다. 시험 자료가 필요하면 “학생 01” 같은 가상 자료만 사용합니다. 현재 버전은 학생 자료를 포함하지 않으며 외부 분석 도구, 외부 글꼴, 데이터 전송 기능을 사용하지 않습니다.

저장 공간은 localStorage(사용 중인 브라우저 안의 저장 공간)입니다. 앱 전용 항목 `puli-process.workspace` 하나만 사용합니다. 다른 기기와 자동 동기화되지 않으며 브라우저 데이터 삭제 시 사라질 수 있습니다. localhost와 GitHub Pages도 서로 다른 저장 공간입니다. `index.html`을 직접 여는 방식은 브라우저에 따라 저장 동작이 달라질 수 있으므로, 저장·복원은 같은 사이트 주소에서 사용하세요. 주소나 기기를 바꿀 때는 JSON 백업으로 옮깁니다. 개인정보가 포함된 백업은 저장소 밖의 별도 안전한 위치에 보관해야 합니다.

## 저장·백업 사용 방법

1. 앱을 열면 빈 보관함을 저장하고 화면 위에 저장 상태를 표시합니다. 현재는 학기·과목 입력 칸이나 예시 자료를 만들지 않습니다.
2. **JSON 내보내기**를 누르면 전체 보관함을 파일로 내려받습니다. 브라우저 다운로드 목록을 확인하고 저장소 밖에 보관하세요.
3. **JSON 가져오기**에서 이 앱으로 내보낸 `.json` 파일을 선택합니다(최대 2MB).
4. 파일 검사 후 나타나는 확인 창에서 **전체 교체하고 저장**을 눌러야 적용됩니다. **취소** 또는 Esc를 누르면 기존 내용은 유지됩니다.

잘못된 JSON, 다른 앱의 파일, 지원하지 않는 버전이나 추가 항목은 거절합니다. **이번 단계는 빈 보관함만 지원하므로 학기·과목 데이터가 있는 파일은 받지 않습니다.** 지원하지 않는 자료를 버리거나 일부만 복원하지 않습니다. 미래 단계에서는 저장 형식 버전과 검사를 함께 확장합니다.

저장 공간 부족·저장 차단 시 성공으로 표시하지 않고 기존 내용을 보존합니다. 원인을 해결한 후 **저장 상태 다시 확인**을 누르세요. 읽을 수 없는 기존 데이터도 자동 삭제하지 않습니다. **현재 저장 원본 보관**으로 원문을 내려받은 뒤 정상 백업을 가져오거나, 확인 창을 거쳐 **빈 보관함으로 초기화**할 수 있습니다. 원본 보관 파일은 손상된 내용일 수도 있으며 정상 백업과 구분해야 합니다. 다른 창에서 저장 내용이 바뀌면 다시 확인하기 전까지 백업 조작을 중단합니다.

### 현재 백업 형식

```json
{
  "format": "puli-process-backup",
  "version": 1,
  "selectedSemesterId": null,
  "selectedCourseId": null,
  "semesters": []
}
```

`version`은 저장 양식의 번호, `semesters`는 향후 학기 목록이 들어갈 자리입니다. 선택 번호는 아직 선택할 과목이 없으므로 `null`(선택 없음)입니다. 현재 형식에는 학생 정보를 넣는 칸이 없습니다.

`.gitignore`는 `node_modules/`, `.env`, `.env.*`, `*.pem`, `*.key`, `backups/`를 업로드 대상에서 제외합니다. 모든 개인정보를 자동 감지하는 장치는 아니므로 커밋 전에 파일 내용을 확인합니다.

## GitHub Pages 설정

1. GitHub 저장소에서 Public 표시를 확인합니다.
2. Settings → Pages를 엽니다.
3. Build and deployment → Source에서 Deploy from a branch를 선택합니다.
4. Branch를 main, 폴더를 /(root)로 선택하고 Save를 누릅니다.
5. 배포가 끝나면 Visit site로 실제 화면을 확인합니다. 실패 시 Actions에서 실행 결과를 확인합니다.

이후 main에 푸시하면 자동으로 다시 배포됩니다. 커밋은 변경 이력 저장, 푸시는 GitHub 업로드를 뜻합니다. 작업 완료 시 확인 후 커밋·푸시합니다.

## 구성과 확인 항목

- `index.html`: 5개 탭, 빈 화면, JavaScript 비활성 안내
- `assets/`: 스타일, 탭 이동, 저장·검사(`storage.js`), 백업 화면 동작(`backup.js`)
- `screenshots/01-first-version.png`: 첫 화면 캡처
- `screenshots/03-before-storage.png`: 저장·백업 추가 전 화면
- `CHECKLIST.md`: AI 초안과 직접 수정한 내용의 비교표. 저장·백업 기록은 사용자가 이유를 말한 뒤 추가합니다.

컴퓨터와 너비 360px 모바일 화면, 백업 내보내기·복원·취소, 잘못된 파일, 저장 공간 부족, 저장 차단, 손상된 저장 내용, 다른 창과의 충돌을 확인합니다. JavaScript가 꺼져 있으면 백업 버튼은 비활성화됩니다.

개발 확인: Node.js가 설치된 환경에서 `node --test tests/storage.test.cjs`로 저장 동작 검사를 실행합니다. 별도 패키지 설치는 필요하지 않습니다.
